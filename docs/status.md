# 현재 상태

## 공개 소스와 제작 상태

- 저장소: <https://github.com/mud-the-developer/hwp-editor-public>
- 현재 소스 제작 버전: `1.0.0-rc.3`.
- WPF 기반 HWPX 작성·검토 소스와 기존 고급 HWP 도구를 포함합니다.
- 공개 소스 URL·문서·고지가 바뀐 소스에는 새 후보 빌드가 필요합니다. 다른 소스의 기존 EXE·ZIP을 공개판과 짝지을 수 없습니다.
- 초안 사전 릴리스는 정식 배포가 아닙니다. 공개 소스의 존재와 바이너리 게시·시험·법적 재배포 준비는 별개입니다.
- 공개판 `v1.0.0-rc.3`의 설치 ZIP은 게시하지 않았습니다. 오프라인 빌드, EXE 자체시험, 읽기 전용 설치 키트 점검은 통과했습니다. 새 무서명 합성 문서를 사용한 실제 한글 시험에서 스키마 1은 통과했지만 스키마 3의 저장본 재개방 후 `section0` 읽기 순서가 `linear="no"`로 바뀌어 중단했습니다. 스키마 4는 미실행이며 증빙·안전 검사 완화나 재시험은 하지 않았습니다. 공개 소스는 `start-desktop.cmd`로 실행할 수 있습니다.

## 제공하는 소스 기능

기본 WPF 화면은 HWPX 라이브 미리보기와 순수 OMP 터미널입니다. 작업 폴더에서의 저장을 자동 감지하고 최초 원본·체크포인트를 보존합니다. 기존 `.hwp` 검토는 별도 데스크톱 창에서 수정안 저장·승인·별도 적용·결과 확인 순서로 진행합니다. 외부 셸은 사용자 권한으로 실행되며 GUI 밖 쓰기를 격리하지 않습니다.

현재 사용자 설치·제거 스크립트와 필수 도구 준비 경로가 있습니다. 이는 Windows의 모든 실제 수명주기에서 검증되었다는 뜻이 아닙니다. 설치 영수증 계약은 `hwp-user-install-receipt-v2`입니다.

현재 작업 소스는 호환 x86 한글이 설치된 경우, 같은 필수 도구 준비 과정에서 한글 자동화 보안모듈을 공식 HTTPS 경로로 받아 검증하고 명시적 동의 후 현재 사용자에게 등록합니다. 한글 미설치·인식된 비호환 비트수는 대상 아님으로 구분하며, 기존 등록의 손상·불일치는 수리하지 않습니다. 준비 명세는 `hwp-windows-dependencies-v3`, 읽기 전용 상태 보고서는 `hwp-requirements-status-v2`이며 모든 항목의 적용 여부와 설치 상태를 구분합니다. 이 소스 변경은 보존된 EXE·ZIP·Draft에 반영됐다는 뜻이 아니며 실제 PC 등록·한글 연동의 검증 결과도 아닙니다.

소스 실행의 `start-*.cmd`는 `.venv`가 없을 때 자동 생성하고 고정 실행 의존성을 설치합니다. 기존 환경은 읽기 확인 후 변경 없이 재사용하며 실패·불완전·버전 불일치는 자동 복구하지 않습니다. 설치된 Python이 필요하고, EXE에는 적용하지 않습니다. 이 소스 변경이 보존된 EXE·ZIP·Draft 릴리스에 반영됐다는 뜻은 아닙니다. [소스 환경 준비](desktop-app.md#개발-소스-준비)

소스 데스크톱의 최초 실행에서는 `build/` 또는 UI 등록이 없으면 프로젝트 전용 SDK 준비와 현재 소스 UI의 빌드·검증·최초 등록을 수행합니다. 정상 등록은 컴파일러 없이 재사용하고, 손상·소스 불일치·미완료 기록은 자동 덮어쓰기나 재시도 없이 보존합니다. 이 절차는 EXE 내장 UI와 기존 문서/Native 권한 검사를 바꾸지 않으며 새 PC 전체 앱 동작이나 새 배포본 qualification의 증거는 아닙니다.

## 검증 주장의 경계

이 문서는 기능·검증 경계의 안내이며 현재 후보의 시험 영수증이 아닙니다. 실제 수행한 검사는 해당 릴리스의 정확한 commit·EXE·검증 manifest로 확인합니다. 과거 검사 수치나 다른 후보의 결과는 승계하지 않으며, 별도 증거가 없는 항목은 **미검증**입니다.

- 합성·모의 SDK/모델/Native 검사는 실제 모델·한글의 양성 검증이 아닙니다.
- frozen EXE의 정확한 UI·터미널·렌더러 동작은 소스 검사와 별개입니다.
- 다른 PC·깨끗한 PC 검증과 실제 Windows 설치/제거·UAC·취소·재부팅·충돌 수명주기를 완료했다고 주장하지 않습니다.
- 코드 서명 완료·전체 재배포 적합성·한글 최종 배치·제출 승인을 주장하지 않습니다.
- 배포 한계 표시는 `redistribution_ready=false`, 서명 미완료, 다른 PC 미검증 상태를 정직하게 유지해야 합니다.

## 유지되는 제한

생성 동의, 정확한 파일 채택, 실제 한글 검수, Native 적용, 제출은 각각 별도입니다. schema1/3/4의 strict 정책, schema2와 generic Native 차단, 외부 binding·입력/출력 해시·소유 인스턴스 검사는 공개판에서도 완화하지 않습니다. 실패·timeout·불명확한 정리에서 멈추며 자동 재시도·cache 수리·강제 종료로 통과시키지 않습니다.
