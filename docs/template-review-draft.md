# 원본 양식 기반 검토 초안

## 지원하는 작업

`template-review-draft-v2`는 원본 HWPX의 **사용자가 확인한 최상위 문단 범위**를 준비된 HWPX 원고의 명시적 문단 범위로 대체하여, 원본 양식을 포함한 **새 미승인 검토용 HWPX**를 만듭니다. 표·그림·개체 캡션을 포함할 수 있습니다.

이 문서는 **고급 준비 원고 HWPX 경로**입니다. 기본 보고서 흐름은 [원본 HWPX·자연어 요청에서 시작](user-guide.md#시작과-문서-선택)하며 준비 원고·XML 번호가 필수가 아닙니다. 자동 텍스트 경로에서 표·그림·제어 개체·혼합 서식이 지원되지 않으면 범위를 확인하거나 여기의 풍부한 원고 구성을 사용합니다. 개체를 버리고 텍스트만 생성하지 않습니다.

원본에서 텍스트만 바꾼 원고처럼, `Contents/section0.xml`을 제외한 **모든 ZIP 항목 이름과 내용 바이트가 원본과 완전히 같을 때만** 기존 자원 문맥을 재사용합니다. 이 경우 기존 글꼴·문단·글머리표·스타일 정의를 다시 가져오거나 재번호화하지 않고 원래 header를 그대로 유지합니다. 새 본문의 직접 참조 누락은 계속 거부합니다. header의 구조적 동등성만으로는 충분하지 않으며, 다른 자원 하나라도 달라지면 기존 외부 원고의 의존 자원 검사·가져오기 경로를 그대로 적용합니다. 특정 글꼴 참조 숫자를 `0`으로 바꾸거나 상속 의미를 추정하는 예외가 아닙니다.

현재 기본 앱은 WPF 기반 HWPX 작성 흐름이며 이 준비 원고 경로는 별도 고급 기능으로 유지됩니다. 정확한 최신 소스·EXE·모델·한글 검증 범위는 [현재 상태](status.md)를 따릅니다. 이 생성 계약은 schema1~4 Native qualification을 변경하지 않으며 실제 쪽수·줄바꿈·번호 재계산·범위 밖 픽셀 불변이나 제출·서명 승인이 아닙니다.

## 생성 뒤 정확한 파일 채택

1. 고정한 원본·원고·작성 범위와 정책을 확인하고 **새 미승인 검토본 생성** 작업을 명시적으로 허용합니다. `/api/template-draft` 한 번으로 기존 엔진의 생성·정상 범위 검사를 수행합니다.
2. 생성된 HWPX를 열거나 내려받아 실제 문구·표·그림·캡션·배치를 검토합니다.
3. **이 수정본 사용**(`/api/template-accept`)은 현재 정확한 파일만 채택합니다. 채택은 생성이나 재생성을 실행하지 않습니다.

기존 `hwp_review.create_review_server`의 `TemplateHandler`만 실제 작업 권한과 파일 채택 기록을 씁니다. Host·Origin·랜덤 token·If-Match·고정 계획/입력 gate를 유지하며 agent/model/다른 서버는 권한을 쓰지 않습니다. 이전 approve/create API 별칭과 옛 v1 승인 권한은 이관 없이 거부합니다. 기존 Native의 정확한 승인·별도 적용 계약은 그대로입니다.

작업 허용은 소유 프로젝트의 새 미승인 파일만 대상으로 합니다. 원본 덮어쓰기·제출·외부 전송·Native 실행을 허용하지 않습니다. 입력·런타임 변경은 새 작업이며 실패·부분 출력·lease·과거 승인은 보존합니다. 결과가 불명확하면 상태만 읽고 자동 재전송하지 않습니다.

## 검토 화면 읽기

기본 화면은 **기존 내용과 수정안을 나란히 보는 텍스트 비교**입니다. 작업이 두 개이면 상단 문서 탭으로 전환합니다. 원본 양식/삽입 원고의 파일명, 교체하는 최상위 문단 수와 새 범위의 표·그림 수를 함께 보여줍니다. 기존 범위에 추가하는 것이 아니라 그 범위를 교체하며, 삽입 원고 파일 전체가 생성 결과는 아닙니다.

- **텍스트 비교**는 같은 추출 문단을 순서대로 맞추고 변경 묶음을 표시합니다. 한 문단끼리 비교할 수 있으면 공백으로 구분한 토큰 기준으로 삭제 문구는 주황색 취소선, 추가 문구는 파란색 밑줄로 강조합니다. `− 삭제`·`+ 추가` 문구와 서로 다른 선 모양을 함께 사용하므로 적록 색각이상이나 흑백 표시에서도 색에만 의존하지 않습니다. 여러 문단이 대체되거나 구간이 길면 묶어서 표시하며, 개체나 원본 문단의 일대일 대응을 추정하지 않습니다.
- 같은 문단은 기본으로 접습니다. **같은 문단도 표시** 또는 **전체 문단 보기**로 전체 추출을 순서대로 확인할 수 있습니다. 이전/다음 변경 버튼은 변경 묶음으로 이동합니다. 좁은 화면에서는 기존 내용 다음에 수정안을 세로로 배치합니다.
- 추출 순서는 HWPX 원본 문단 번호가 아닙니다. 추출 텍스트가 같아도 서식·표·그림·배치가 같다는 뜻은 아니며, 추출이 비어 있어도 내용이나 변경이 없다고 판정하지 않습니다.
- **그림 비교**는 내장 PNG 확인용입니다. **범위·자원 상세**에는 앞뒤 경계, 파일 위치와 SHA256, 정확한 0기준 반개구간, 자원/글꼴 추가와 캡션·참조 정책이 있습니다. 탭 전환·본문 펼치기·변경 이동은 작업 허용·생성·채택을 실행하지 않습니다.
- 명시적 작업 동의 후 미승인 검토본을 생성합니다. 생성 뒤 파일 링크와 **이 수정본 사용**을 제공합니다. 과거의 승인 후 최초 생성 단계를 사용하지 않으며 실제 HWPX 검토 전에는 채택하지 마세요.

## 그림 변경 확인 — PNG 원본, 문서 렌더링 아님

**그림 비교** 탭을 처음 열면 정확한 원본 대체 범위와 메모리에서 컴파일한 새 삽입 범위의 그림을 확인합니다. 그림의 내장 자원 SHA256과 저장된 개체 크기는 각 그림의 접힌 상세에 있으며, PNG는 원본 크기로 열 수 있습니다. 텍스트 비교만 볼 때에는 그림을 요청하지 않습니다.

- PNG 바이트와 그림 XML 속성을 함께 대조합니다. 같은 PNG라도 크기·자르기·회전 설정이 바뀌면 비교 대상에 남고, 같은 항목은 중복 개수까지 대응시켜 생략합니다. 기존/새 목록은 일대일 개체 대응이나 문서 전체 변경 목록이 아닙니다.
- 자원·개체 식별자와 그리기 순서의 재할당, 캡션 XML은 이 대조에서 제외합니다. 캡션 내용은 추출 텍스트에서 별도로 확인합니다. 생략된 그림이 있다고 문단·레이어·문서 배치가 같다고 판정하지 않습니다.
- **PNG 픽셀만 표시합니다. 자르기·회전·겹침·캡션 배치나 한글 쪽 배치를 재현하지 않습니다.** 같은 PNG가 보이더라도 실제 HWPX 확인은 필요합니다.
- PNG 미리보기는 파일당 8 MiB, 1,600만 픽셀까지입니다. 비PNG·불명확한 이미지 참조·잘못된 형식·초과 크기는 변환하거나 다른 자원으로 대체하지 않습니다. 미리보기 제한을 입력 문서의 편집 허용이나 Native 검증으로 확대하지 않습니다.
- 읽기 요청은 기존 Host/token과 정확한 plan hash·현재 스냅샷/범위를 검사합니다. 경로나 ZIP 항목을 요청으로 지정할 수 없고 범위 밖 이미지는 노출하지 않습니다. 후보·계획·승인·결과 파일은 쓰지 않으며, 저장된 계획/preview hash와 생성 바이트 형식은 바꾸지 않습니다.

## 작업·생성·채택 상태

작업 허용 전, 생성 중/실패, 검토본 생성 완료·미채택, 정확한 파일 채택을 구분합니다. 완료 표시는 선언한 결과 경로·바이트가 모두 검증될 때만 제공하며 내려받기와 채택도 현재 파일을 다시 확인합니다.

실패·부분 출력·누락·변조는 완료나 채택으로 표시하지 않습니다. 기존 lease·실패 기록을 지우거나 자동 재시도하지 않습니다. 수정된 파일은 이전 채택을 승계하지 않으며 외부 수정본은 원래 구조·범위 검사 후 새 미채택 버전으로 가져옵니다. 실제 한글 검수·제출 승인은 별도이며 화면은 Native를 자동 실행하지 않습니다.

기존 검토 서버 프로세스는 새 코드를 자동으로 읽지 않습니다. 새 기능 확인에는 새 소유 서버를 사용하고, 진행 중인 기존 작업이나 서버를 임의 종료하지 않습니다.

## 실행

기존 `.venv`에서 실행합니다. 환경·보안 모듈·한글·레지스트리 설치나 변경은 필요하지 않습니다.

```text
.venv\Scripts\python.exe scripts\hwp_review.py template-draft-prepare work\toy-profile.json work\NEW-template-review
.venv\Scripts\python.exe scripts\hwp_review.py template-draft-review work\NEW-template-review --port 8766 --open
```

위 직접 CLI는 고급 개발 소스 실행 예시입니다. frozen에서는 유효한 report binding을 가진 프로젝트만 허용하며 원시 unbound 서버는 거부합니다. 다른 소스/frozen·EXE·기기·사용자의 권한은 이관하지 않습니다.

프로필은 자동 추측 결과가 아니라 정확한 파일 hash와 범위를 명시한 제안입니다. 범위는 `Contents/section0.xml`의 최상위 자식에 대한 **0부터 시작하는 반개구간**입니다. 앞뒤 경계를 모두 남겨야 하므로 전체 문서 교체는 지원하지 않습니다.

```json
{
  "contract": "template-review-draft-v2",
  "jobs": [
    {
      "label": "합성 시험 양식의 지정 작성 영역",
      "source": "source.hwpx",
      "source_sha256": "정확한 원본 SHA256",
      "payload": "payload.hwpx",
      "payload_sha256": "정확한 원고 SHA256",
      "target_range": [2, 3],
      "payload_ranges": [[0, 2]]
    }
  ]
}
```

작업은 최대2개입니다. 프로필이 양식을 수정하거나 승인하지는 않습니다. 준비 단계는 dry-run으로 생성 예정 바이트·검증 결과를 산출하지만 candidate 파일은 쓰지 않습니다. 출력 디렉터리는 새로 생성하며 기존 baseline/PDF를 위장하거나 재사용하지 않습니다.

## 정적 보존 계약

- 단일 section만 지원하며 앞뒤 경계·기존 선택 문단의 XML hash와 정확한 source/payload hash를 결합합니다.
- 원본과 입력 원고는 덮어쓰지 않습니다. `inputs/`의 immutable snapshot도 해시로 재검사합니다.
- 원본의 범위 밖 XML subtree와 기존 자원 정의를 보존합니다. 문서 전체 XML 바이트·네임스페이스 prefix가 같다는 의미는 아닙니다.
- 원본 ZIP의 기존 BinData·settings·scripts·미리보기 이미지 등 잠긴 항목은 byte 동일합니다. 선언된 section/header/OPF manifest/미리보기 텍스트만 변경하고 PNG 자원만 추가합니다. 원래 scripts는 잠긴 원본 데이터로 보존할 뿐 실행하지 않습니다.
- 승인된 원고에서 실제로 도달 가능한 글꼴·문자·문단·스타일·테두리·탭 등만 새 ID로 추가합니다. 원본 ID·기존 정의·기존 이름은 변경하지 않습니다. 사용하지 않는 템플릿 잔여 정의를 가져오지 않으며, 실제 필요한 참조가 없으면 거부합니다.
- 원고의 그림 ID·경로·문단/개체 ID를 분리하고 원본 OPF 항목·spine·메타데이터를 보존합니다. 기존 원본의 중복 ID를 임의 수리하지 않습니다.
- 줄 캐시는 가져온 문단 내부에서만 제거합니다. 원본 전체의 캐시를 지우지 않습니다.
- 기존 프로필은 picture-owned bottom caption과 PICTURE 캐시 번호1부터의 기존 정책을 그대로 사용합니다. 아래 명시적 `caption_policy`를 선택한 새 제안에 한해서 표·그림 개체 캡션과 같은 작성 영역의 본문 상호참조를 지원합니다. 기존 수동 캡션·승인 결과를 소급 수정하지 않습니다.
- 원고가 원본 열 폭을 초과하면 차단합니다. 글꼴·표·그림·쪽을 줄여 맞추지 않습니다. 원래 페이지 속성은 유지합니다.
- 서명·암호화·복수 section·DTD/주석/PI·미지원 제어 개체·미해결 참조·외부/비PNG 자원은 지원 범위 밖입니다. 이를 보안 인증으로 확대하지 않습니다.

새 문단이 들어가면 뒤 내용의 **쪽 흐름은 달라질 수 있습니다**. 이 계약은 고정 쪽수·고정 영역 Native 편집 계약을 완화한 것이 아니라, 사용자가 별도로 확인한 **재흐름 가능한 검토 초안 생성**입니다. 실제 한글 저장·재개방·쪽 배치는 이후 별도 확인이 필요합니다.

## 개체 캡션과 본문 번호 참조 — 명시적 선택

새 job에 `"caption_policy": "owned-table-picture-crossref-v1"`를 지정하면 다음의 닫힌 모델만 사용합니다. 이 필드는 계획 hash와 정확한 UI 승인 범위에 포함됩니다. 생략한 기존 프로필의 생성 바이트·미리보기 정책은 유지합니다.

- 표는 `hp:tbl/hp:caption side="TOP"`과 TABLE 자동 번호, 그림은 `hp:pic/hp:caption side="BOTTOM"`과 PICTURE 자동 번호를 각각 하나 가집니다. 별도 일반 문단을 캡션처럼 보이게 하는 방식이 아닙니다.
- 원고 내부 캐시 번호는 종류별1부터입니다. 컴파일 시 원본의 앞쪽 `numberingType`을 가진 모든 개체를 세어 이어 번호를 계산합니다. 그룹/container도 포함합니다. 저장된 캐시와 본문 참조는 같은 번호를 사용합니다.
- 본문은 동일한 승인 작성 영역 안의 표·그림만 가리키는 native CROSSREF 번호 필드로 제한합니다. 8개 정해진 parameter·번호 캐시·begin/end 쌍·대상 객체 ID 관계를 검사하고, 가져오는 객체/field ID와 `instid`·`beginIDRef`·`RefPath`·`Command`를 함께 재매핑합니다. 외부 경로·책갈피·임의 field·중첩/미해결 참조는 허용하지 않습니다.
- 원본 시작 번호는 표·그림 모두1이어야 합니다. 번호 재시작·범위 밖 자동 캡션/상호참조는 거부합니다. 범위 뒤의 번호가 있는 개체는 해당 종류의 대체 전후 개체 수가 같아 순번이 바뀌지 않을 때만 보존합니다.
- 독립 검증기도 저장 바이트에서 캡션 소유·번호·참조 연결을 다시 검사합니다. UI는 캡션/참조 개수와 기존 개체의 번호 기준을 표시합니다.

이는 **HWPX 구조 지원**입니다. 실제 한글의 메뉴 인식·이동/삭제 후 갱신·폰트/표/캡션 쪽 배치·Native 저장 보존을 검증했다는 뜻이 아닙니다. 앞선 합성 그림 캡션 관측을 새 표/상호참조 기능의 Native qualification으로 재사용하지 않습니다.

형식 근거(소프트웨어/포맷 자료, 보고서 연구 성과 출처 아님): [python-hwpx 개체 캡션 모델](https://github.com/airmang/python-hwpx/blob/main/src/hwpx/oxml/objects.py), [HwpForge native CROSSREF 8-parameter 형식](https://docs.rs/hwpforge-smithy-hwpx/latest/src/hwpforge_smithy_hwpx/encoder/section/field.rs.html), [참조 종류·내용 enum](https://docs.rs/hwpforge-foundation/latest/src/hwpforge_foundation/enums/reference.rs.html).

## 검증

`tests/test_template_draft.py`·`tests/test_report_document_http.py`·`tests/test_review_ui.mjs` 등은 합성 입력의 구조·범위·자원·요청 보호·실패 보존·결과 무결성을 검사하기 위한 코드입니다. 이 문서는 공개 복사본에서 해당 검사를 실행했다는 결과가 아닙니다.

합성·모의 검사는 실제 한글 보존 검증이나 최종 시각 검토가 아닙니다. 새 UI 작업 허용·생성·정확한 파일 채택과 frozen 동작은 해당 공개 후보에서 별도 확인해야 합니다. 원고가 외부에서 변경되면 과거 proof를 승계하지 말고 현재 hash를 새 제안에 결합합니다. [현재 상태](status.md) · [릴리스 규칙](releases.md)
