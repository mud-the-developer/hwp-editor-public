HWP Editor 1.0.0 — HWPX 보고서 작성용 Windows x64 배포 패키지
Windows Presentation Foundation (WPF) 한 창의 문서·수정본 트리 / 가운데 HWPX 연속 쪽 / 오른쪽 같은 OMP 대화·수정 메모로 작성합니다.
실제 후보의 버전·EXE·소스·검증 범위는 동봉 manifest와 체크섬으로 확인하세요.
처음 사용한다면 동봉된 사용법.txt를 먼저 읽으세요.
기존 HWP 자동적용은 별도 고급 도구이며 이 HWPX v1의 검증 완료 기능이 아닙니다.
이 패키지는 현재 소스로 새로 제작한 배포물입니다. 실제 화면 모양·메모·@ 파일 선택·일괄 전송의 최종 확인은 사용자가 진행합니다.
동봉 검증 기록에 없는 실제 GUI·유료 모델·한글·다른 PC의 성공을 통과로 간주하지 마세요.

다른 PC에서 설치하기 — 현재 사용자용 설치 스크립트
1. 새 키트 ZIP을 고정 로컬 드라이브의 새 폴더에 전부 풉니다. ZIP 안에서 실행하지 마세요.
   과거 EXE/ZIP에는 이 기능이 없습니다. 기존 build/work/candidate를 덮어쓰지 마세요.
2. 신뢰할 수 있는 별도 전달 경로의 ZIP SHA-256과 출처를 확인하세요.
   동봉 해시/manifest는 바이트 일관성 검사이며 코드 서명이나 배포 허가가 아닙니다.
3. Install-HWPReview.cmd를 실행합니다. Windows PowerShell 5.1을 사용하므로 PowerShell 7이 없어도 시작됩니다.
   앱·정확한 소스·고지·설치 스크립트의 전체 목록/크기/SHA-256과 빌드 입력 결합을 먼저 확인하고,
   같은 HWPReview.exe --check-requirements로 필수 항목을 확인합니다. 누락분은 기존
   --setup-requirements 준비 창 한 경로로 설치하고 실제 상태를 다시 확인합니다.
   래퍼 자체를 관리자 실행할 필요는 없지만 Microsoft 설치기의 약관·개인정보 안내·UAC는 직접 확인합니다.
   실패·취소·불명확한 결과·재부팅 필요 시 중단합니다. 자동 재시도·복구·롤백·재부팅은 없습니다.
4. 기본 설치는 %LOCALAPPDATA%\Programs\HWPReview, 시작 메뉴와 제거 등록(HKCU)은 현재 사용자용입니다.
   기존 설치/파일/바로가기/등록을 덮어쓰지 않습니다. 동일 영수증·전체 해시·등록만 already_installed입니다.
   다른 버전의 자동 업그레이드, .hwpx 기본 앱·전역 PATH·문서·기존 로그인/설정 변경은 없습니다.
5. 완료 후 시작 메뉴의 HWP Editor를 직접 엽니다. 설치기는 앱·모델·한글을 자동 실행하지 않습니다.
   Python은 EXE에 포함됩니다. 앱 사용에 .NET SDK나 개발용 Python은 필요하지 않습니다.
   한글·보안 DLL·COM cache는 설치·등록·수리하지 않습니다. 실제 문서 배치는 별도 사용 허가된
   한글에서 HWPX 검토 사본을 직접 열어 확인하세요.

설치 후 앱에서 작업하기
1. 왼쪽 폴더 버튼 또는 Ctrl+O로 HWPX가 있는 작업 폴더나 빈 폴더를 엽니다.
   트리에서 문서·양식을 고르거나 문서 버튼/Ctrl+Shift+O로 다른 위치의 HWPX 양식을 직접 선택합니다.
   파일이 없다면 ＋/새 HWPX 만들기/Ctrl+N으로 작업 폴더 안에 실제 빈 파일을 만듭니다. 기존 파일은 덮어쓰지 않습니다.
   작업 기록은 .hwpreview/Projects에 보관하며 같은 파일은 검증한 기존 작업을 다시 엽니다. 폴더 열기·목록·새 빈 원본 생성만으로 모델에 보내거나 초안 권한을 만들지 않습니다.
   작성 전에는 오른쪽 OMP 로그인으로 시작으로 앱 전용 터미널에서 /login과 모델 선택을 직접 합니다.
   ‘대화 화면으로’에서 HWPX 없이도 대화할 수 있습니다. 선택 폴더가 실제 OMP 작업 경로이며 변경 시 유휴 세션을 정상 종료하고 같은 앱 프로필로 새 경로에 연결합니다.
   기본 OMP 읽기·쓰기·셸을 사용합니다. 프로젝트의 HWPReview.md는 없을 때만 만들고 기존 파일은 보존합니다. Markdown은 지침이지 보안 경계가 아니며 셸은 사용자 권한으로 프로젝트 밖에도 접근합니다. GUI의 생성·채택·승인 절차와는 별개입니다.
2. 가운데 문서를 위아래로 스크롤하고 본문을 두 번 클릭해 인용문이 붙은 수정 메모를 작성합니다.
   메모는 원본/수정본의 해시·실제 문단에 연결되며 모호한 위치나 지원하지 않는 표 셀·머리말/각주를 가까운 본문으로 추측하지 않습니다.
   메모·추가 요청 입력란에서 @를 치면 명시적으로 연결한 폴더/파일의 이름을 퍼지 검색할 수 있습니다.
   ↑↓와 Tab/Enter 또는 클릭으로 고른 UTF-8 텍스트·코드/HWPX 본문 발췌만 로컬 전송 대기에 추가합니다.
   문서 속 @경로·^표기는 자동 파일 첨부나 모델 선택이 아니며 자료 선택·미리보기만으로 모델을 호출하지 않습니다.
3. 보내기/Ctrl+Enter는 일반 대화입니다. 문서 수정은 수정안 요청으로 선택 본문·자료·메모를 한 번 전송합니다.
   대화 중 폴더 자료를 읽는 경우에도 모델 사용료가 발생할 수 있습니다. 현재 문맥·정상 완료·실제 유휴를 확인한 문서 수정안만 검사합니다.
   문서 수정용 내부 JSON은 대화에 흘려보내지 않고, 정상 완료·요청 일치 검사 뒤 수정 본문과 요약을 표시합니다. 원문은 범위·자료 설정의 고급 정보에서 읽을 수 있습니다.
   수정본 만들기 클릭이 별도 미승인 생성 동의이며 답변 도착만으로 생성하거나 모델을 다시 호출하지 않습니다.
4. 새 수정본은 가운데와 트리에 표시합니다. 한글 검토·가져오기/내보내기·정확한 버전 사용은 문서 상단 ⋯ 메뉴에서 합니다.
   로컬 표시는 한글의 최종 배치 검수와 다를 수 있습니다. 버전 사용은 재생성·제출·서명 승인이 아닙니다.
   실행 중·상태 미확인은 생성·닫기·전환을 막습니다. 유휴 상태의 종료/창 닫기는 실제 소유 자식 종료를 기다립니다.

필수 환경 자동 준비 — 기존 앱 준비 창 하나를 재사용
- .NET 10 Desktop Runtime x64, WebView2 Runtime, Bun1.4.4/OMP18.15.0, PowerShell7, Propo 글꼴이 필수입니다.
  호환 설치는 유지하며 누락분만 고정 공식 배포·크기·SHA-256·해당 Microsoft 서명 조건으로 준비합니다.
  일반 .NET Runtime만으로 Desktop Runtime을 대신할 수 없습니다.
- .NET은 관리자 UAC가 필요할 수 있습니다. WebView2 Runtime의 원문 약관·기본 SmartScreen 정보 전송·
  Evergreen 자동 업데이트를 확인하세요. 공유 Microsoft Updater가 설치 범위를 결정할 수 있습니다.
- 새 외부 Runtime/Bun/OMP가 필요하면 준비 창에서 약관 안내를 확인한 뒤 시작합니다.
  필수 항목의 선택 해제는 없으며 AI가 약관 수락·UAC·로그인/인증을 대신하지 않습니다.
- Setup-Requirements.cmd와 HWPReview.exe --setup-requirements도 같은 준비 창입니다.
  상태만 확인하려면 HWPReview.exe --check-requirements <아직 없는 로컬 JSON 경로>를 사용합니다.
  설치/모델/GUI를 실행하지 않으며 종료 코드0=준비 완료,2=누락,1=확인 실패입니다.
  기존 파일·잘못된 경로의 거부도 오류창 없이 종료1로 끝나며 파일을 덮어쓰지 않습니다.
- Windows PowerShell5.1을 유지합니다. PowerShell7 MSI는 대화형이며 PATH·원격 기능·Microsoft 자동 업데이트를
  기본 해제합니다. Nerd Fonts3.5.1 D2Coding 계열의 Propo Regular/Bold만 현재 사용자 글꼴로 준비합니다.
  실제 이름은 D2KodingLigature Nerd Font Propo이며 문서·터미널의 기본 글꼴은 바꾸지 않습니다.
- Bun/OMP는 정확한 기존 설치를 재사용하거나 앱 전용 버전별 Dependencies에 새로 준비합니다.
  기존 ~/.bun·인증·개인 프로필·전역 PATH는 복사/덮어쓰기하지 않습니다. Lifecycle script는 실행하지 않습니다.
- 외부 바이너리는 ZIP에 동봉하지 않습니다. 원문 고지/출처 수집만으로 결합 글꼴 provenance,
  전체 대응 소스 의무나 법적 재배포 적합성이 인증되지는 않습니다.
- 환경 준비 로그는 %LOCALAPPDATA%\HwpReview\SetupRuns, 설치/제거 로그는
  %LOCALAPPDATA%\HWPReview\InstallRuns의 새 작업 폴더에 보존합니다. 실패·취소·부분 설치도 삭제/수리하지 않습니다.

제거와 AI 설치 안내
- Windows 설정의 설치된 앱에서 HWP Editor를 제거하거나 설치 폴더의 Uninstall-HWPReview.ps1을 실행합니다.
  영수증·manifest·정확한 해시가 소유한 파일/바로가기/등록만 대상으로 합니다. 재귀 삭제하지 않습니다.
- 실행 중인 앱은 직접 정상 종료하세요. 변경/추가된 파일·등록/바로가기·사용자 폴더는 보존합니다.
  보존이 필요하면 종료 코드3과 retained 목록을 남깁니다. 핵심 파일 삭제의 사전검사 실패 시
  제거 엔진·wrapper·manifest·영수증4개를 함께 보존합니다. 삭제 도중 커널/저장장치 오류나 프로세스 중단은
  원자적 작업이 아니므로 부분 상태가 남을 수 있습니다. 로그를 보존하고 자동 재시도/복구하지 마세요.
  문서·Projects·AppData·인증/프로필·공유 .NET/WebView2/PowerShell/글꼴/Bun/OMP는 제거하지 않습니다.
- 소유권은 hwp-user-install-receipt-v2입니다. 검증한 log_directory와 경로 표기를 보관하고 Windows 제거 명령과
  기본 제거 wrapper가 같은 설정을 사용합니다. 옛 영수증을 수정하거나 다른 후보 파일과 섞지 마세요.
- 설치/제거는 hwp-install-operation-v1 JSON입니다. 0=완료/동일 설치/이미 없음,1=실패,
  3=경로/소유권/충돌/보존,4=앱 실행 중,5=필수 준비 실패,1602=취소,3010=재부팅 필요입니다.
- AI에게는 동봉 AI-INSTALL.md와 실제 설치 키트를 전달하세요. 먼저 -Operation Check로 변경 없이
  파일/해시/경로/충돌만 확인합니다. EXE·필수 항목 확인기를 실행하지 않으므로 준비 완료 증거는 아닙니다.
  AI는 별도 설치 명령·winget·임의 스크립트로 우회하거나 약관·UAC·로그인을 대신 승인하지 않습니다.

저장 위치와 PC 이동
- 기본 새 프로젝트: %LOCALAPPDATA%\HwpReview\Projects. 원본은 덮어쓰지 않고 새 사본을 만듭니다.
- 새 WPF 수정 메모는 현재 창과 해당 원본/수정본에 임시 보관합니다. 앱 종료 뒤 자동 저장되는 메모장이 아니며 미전송 메모가 있으면 종료 전에 확인합니다.
- 선택 자료는 로컬 스냅샷이며 모델에 보낼 때만 공유합니다. 원본 텍스트/코드512KiB, HWPX64MiB, 추출 UTF-8자료64KiB, 전체 모델 공유 문맥32KiB 한도를 넘으면 자동으로 자르지 않습니다.
- GUI의 문서 없는 @ 선택도 동일한 원본512KiB/HWPX64MiB·추출64KiB 한도를 사용합니다. 기본 OMP 도구·셸에는 앱의 제한을 적용하지 않습니다. 이미 모델에 전달한 자료는 선택 해제로 회수되지 않습니다. OMP 자체 설정에 따른 작업·사용료를 확인하세요.
- 기존 고급 도구의 메모 내보내기·대화 삭제/비우기는 해당 도구의 데이터에만 적용하며 프로젝트·원본·승인·lease·실패·기존 결과를 지우지 않습니다.
- 검토 workspace는 경로/hash/승인/환경에 묶여 있습니다. 다른 PC로 폴더를 옮겼다고 기존 승인을
  재사용하지 마세요. 다른 PC에서는 새 작업과 정확한 검토·승인을 준비합니다.
- 결과 HWP/HWPX를 단순히 복사해 한글에서 읽는 것과, 기존 승인 작업을 이어 실행하는 것은 다릅니다.
- 폰트/한글 버전/보안 정책에 따라 표시·동작이 달라질 수 있습니다. 한글·글꼴·서명·직인·계정은 동봉하지 않습니다.

문제 발생 시
- 누락된 모듈/동봉 파일: ZIP을 전부 풀었는지와 해시를 확인하세요. 임의 pip 설치로 EXE를 수리하지 마세요.
- 한글/COM 실패: 이 PC에서 한글이 수동 실행되는지, 설치/등록 상태를 담당자와 확인하세요.
- 보안 모듈 누락/불일치: 승인된 공급자/관리자에게 확인하세요. 임의 DLL 교체나 레지스트리 변경을 하지 마세요.
- cache 변경 차단: 기록을 보존하고 중단하세요. cache 전체 삭제·재생성·재설치로 우회하지 마세요.
- 권한/경로 오류: 쓰기 가능한 로컬 폴더를 선택하세요. 실패 workspace를 덮어쓰거나 잠금을 풀지 마세요.
- 서명되지 않은 실행 파일이라 SmartScreen 경고가 표시될 수 있습니다. 보안 프로그램을 끄지 말고 출처/해시로 판단하세요.

지원 범위와 검증 구분
- 기본 HWPX 흐름은 원본·요청·미승인 생성·검토 사본·가져오기·정확한 버전 선택·후속 작성입니다.
  텍스트 전후 비교는 실제 한글 쪽 렌더링이 아닙니다. 표·그림·혼합 서식 미지원 범위를 단순화하지 않습니다.
  원본·기준 파일·기존 버전·실패·승인은 보존하며 범위·모델·자료·기준 변경은 새 동의를 요구합니다.
- 소스/EXE·기기/사용자·규칙이 다른 권한은 재사용하지 않습니다. 구형 권한 기록도 자동 이관하지 않습니다.
  현재 소스는 hwp-report-harness-v3/v2와 hwp-report-runtime-v2를 사용하며 모든 선언 source hash를 결합합니다.
  보존된 기존 후보의 v1 런타임/권한을 새 소스에 이관하거나 새 기능 검증으로 계산하지 않습니다.
- 기존 HWP 도구의 schema1 글자 교체·schema3 표 행 높이·schema4 무날인 빈칸은 기존 strict 계약 대상입니다.
  Source 목록은 새 EXE의 Native qualification이 아닙니다. 과거 GUI4 저장본 metadata 실패는 해결됐다고
  표시하지 않으며, schema2·NO/unknown·병합/복잡한 표·비어 있지 않은 칸·generic Native 차단도 유지합니다.
- 소스 합성 검사, 모의 provider/OS의 실제 WPF 흐름, frozen 자기시험, 실제 모델·한글·다른 PC 검증은
  각각 구분합니다. 동봉 검증 기록에 없는 결과를 통과로 계산하지 마세요.
- 보존 rc.4의 승인 후 browser helper 대기 중단·출력 없음·Native 없음 시도는 재개하지 않습니다.
- 원본·baseline·범위 밖 내용·글꼴·표·그림·캡션·참조·실패·승인을 보존합니다.
- 저장 HWP 재개방·구조·쪽·영역 밖 픽셀 등의 gate를 통과하지 못하면 결과를 제출용이라고 표시하지 않습니다.
- 사람의 원본/결과 시각 검토와 기관 제출·서명 승인은 별도입니다. 다른 PC/한글 버전은 아직 미검증입니다.

실제 OMP 터미널
- 외부 준비 대상은 고정 Bun1.4.4 Windows x64 일반 빌드, OMP18.15.0과 WebView2 Runtime입니다. 누락분은 같은 필수 준비 경로로 검증하며 동봉 바이너리나 다른 버전으로 대체하지 않습니다.
- 앱 전용 HOME/프로필/작업/세션을 쓰며 기존 사용자 인증/설정을 복사하지 않습니다. 선택적 초기 안내만 생략하고 로그인·모델 설정은 직접 합니다.
- 확인한 문맥을 GUI에서 명시적으로 전송하며 사용료가 발생할 수 있습니다. 시작·문서 열기·미리보기는 모델 호출이 아닙니다.
- 현재 GUI 요청에 맞는 정상 완료 공개 제안만 실제 실행 종료·유휴 후 검사합니다. 터미널 자유 대화는 참고용이며 생성·승인 권한이 아닙니다.
  일반 터미널 질문은 자연어로 답하며 JSON 형식을 강제하지 않습니다. GUI가 명시적으로 보낸 문서 수정 요청만 닫힌 제안 JSON을 사용하고 기존 검사를 유지합니다.
- 현재 요청 중단은 요청일 뿐 완료가 아닙니다. 유휴 상태에서는 OMP 정상 종료/창 닫기를 사용하고 실제 종료를 기다립니다. 강제 종료·재연결·재전송·모델 fallback은 없습니다.
- 기존 HWP/managed Pi 고급 도구는 별도 미검증 경로이며 기본 OMP의 실행기/SDK fallback이 아닙니다.

정확한 외부 Bun/OMP 준비
- source ZIP의 packaging/windows-dependencies.json과 packaging/omp-runtime.json을 사용합니다.
  후자는 frozen 앱의 native-ui/omp-runtime.json에 배치되며 기존21개 파일/크기/SHA256/닫힌 namespace 기준은 같습니다.
  임의 PATH의 다른 omp.exe로 우회하지 않습니다. 버전 문자열만으로 연결 가능하다고 보지 않습니다.
- 정확한 기존 사용자 ~/.bun을 재사용하거나 %LOCALAPPDATA%\HWPReview\Dependencies의 새 버전별 root에 준비합니다.
  사용자 전역 설치가 지원 기준과 다르면 건드리지 않고 새 앱 전용 설치를 준비합니다.
  이미 존재하는 앱 전용 root가 변경/충돌이면 중단하며 사용자 root로 fallback/자동 수리하지 않습니다.
- 공식 Bun 고정 ZIP과 실제 bun.exe를 검증하고 고정 OMP를 온라인으로 준비한 뒤 전체21파일을 확인합니다.
  실패 staging·받은 파일·로그를 보존합니다. 계정·개인 프로필은 복사하지 않고 앱 전용 OMP에서 직접 로그인합니다.
